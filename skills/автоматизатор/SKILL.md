# Нейроавтоматизатор

Берёт дело, которое человек делает руками каждую неделю, и превращает в команду из одной строки.

Правило отбора простое: **если задача повторяется чаще раза в неделю и занимает больше десяти минут, её надо автоматизировать.** Всё остальное дешевле сделать руками.

## Железное правило безопасности

**Ничего не удалять и не перезаписывать без явного подтверждения.** Скрипт, который трогает файлы, пишется в три захода:

1. **Режим просмотра.** Скрипт печатает, что он собирается сделать, и ничего не делает.
2. **Показать вывод пользователю** и дождаться «да, поехали».
3. **Боевой запуск** — и только по копии, если файлы важные.

Ни один скрипт не запускается сразу на боевых данных. Сначала копия папки, потом всё остальное.

## Шаг 1. Понять рутину

Не бросайся писать код. Сначала разбери задачу вслух:

1. **Что делаешь руками, по шагам.** Прямо по действиям: открываю, копирую, переименовываю.
2. **Как часто и сколько занимает.** Это решает, стоит ли овчинка выделки.
3. **Откуда берутся данные и куда кладутся.** Папка, таблица, сайт, бот.
4. **Что будет, если ошибиться.** Пропадут файлы или просто придётся перезапустить. От этого зависит, сколько защиты нужно.

Посчитай выгоду вслух: «делаешь два раза в неделю по двадцать минут — это тридцать часов в год». Иногда после этого выясняется, что автоматизировать не надо, надо перестать это делать.

## Шаг 2. Выбрать инструмент

| Задача | Чем делать |
|--------|-----------|
| Файлы: переименовать, разложить, найти | bash или Python |
| Видео и аудио: нарезать, сжать, конвертировать | ffmpeg |
| Таблицы: посчитать, свести, отфильтровать | Python + csv (или pandas, если данных много) |
| Скачать со страницы | Python + requests |
| Телеграм: отправить, забрать, разослать | Python + requests к Bot API |
| Запуск по расписанию | cron на Linux, launchd или cron на macOS |

Выбирай самое простое, что решает задачу. Скрипт на двадцать строк, который понятен через полгода, лучше красивой программы с классами.

## Шаг 3. Написать по шаблону

Любой скрипт собирается по одной схеме:

```python
#!/usr/bin/env python3
"""Что делает скрипт. Как запускать."""

import sys
from pathlib import Path

DRY_RUN = "--go" not in sys.argv   # без --go только показывает, что сделает

def main():
    src = Path("папка")
    if not src.exists():
        print(f"Нет папки {src}")
        return 1

    for f in sorted(src.iterdir()):
        new_name = ...                       # что хотим получить
        print(f"{f.name}  ->  {new_name}")
        if not DRY_RUN:
            dest = f.with_name(new_name)
            if dest.exists():
                print(f"Пропуск: целевой файл уже существует: {dest}")
                continue
            f.rename(dest)

    if DRY_RUN:
        print("\nЭто был просмотр. Запусти с --go, чтобы применить.")
    return 0

if __name__ == "__main__":
    sys.exit(main())
```

Обязательные части любого скрипта:

- **Комментарий сверху:** что делает и как запускать. Через месяц никто не помнит.
- **Проверка входа:** есть ли папка, есть ли файлы, тот ли формат. Падать надо сразу и понятно.
- **Режим просмотра** для всего, что меняет или удаляет.
- **Печать прогресса.** Молчащий скрипт на сто файлов выглядит как зависший.
- **Понятная ошибка вместо трейсбека.** «Не нашёл файл config.json рядом со скриптом» лучше пяти экранов Python.

## Шаг 4. Проверить

Порядок проверки, который экономит нервы:

1. Сделай копию данных: `cp -R боевая_папка проверка`
2. Запусти скрипт на копии в режиме просмотра.
3. Покажи вывод пользователю: «вот что произойдёт, всё верно?»
4. Запусти на копии по-настоящему и проверь результат глазами.
5. Только теперь на боевых данных.

Если данных много — сначала прогони на первых пяти файлах.

## Шаг 5. Поставить на расписание

Когда скрипт отлажен и просят запускать регулярно:

```bash
# Открыть расписание
crontab -e

# Каждый день в 9 утра
0 9 * * * cd /путь/к/папке && /usr/bin/python3 report.py --go >> log.txt 2>&1

# Каждый понедельник в 10
0 10 * * 1 ...

# Каждый час
0 * * * * ...
```

Что обязательно:

- **Полные пути.** В расписании нет твоих переменных окружения, `python3` может не найтись.
- **Лог в файл.** Без `>> log.txt 2>&1` ошибки уходят в никуда и потом непонятно, почему не сработало.
- **Уведомление о результате.** Проще всего сообщением в Telegram — тогда сразу видно, что скрипт живой:

```python
import requests
requests.post(
    f"https://api.telegram.org/bot{TOKEN}/sendMessage",
    data={"chat_id": CHAT_ID, "text": "Отчёт собран: 42 строки"},
    timeout=20,
)
```

На macOS cron может не иметь доступа к папкам Документы и Рабочий стол. Если задание молчит — либо дай терминалу полный доступ к диску в настройках приватности, либо держи рабочие файлы в отдельной папке в домашней директории.

## Частые задачи и решения

**Разложить фото и видео по датам:**
читаем дату изменения файла, создаём папку `ГГГГ-ММ`, перекладываем.

**Сжать все видео в папке:**
```bash
for f in *.mp4; do
  ffmpeg -i "$f" -vcodec libx264 -crf 26 -preset fast "сжатые/$f"
done
```

**Свести несколько выгрузок в один отчёт:**
Python читает все csv из папки, складывает нужные колонки, пишет итог в новый файл. Обязательно печатать, сколько строк прочитано из каждого файла: так сразу видно битую выгрузку.

**Проверять сайт или бота раз в час:**
запрос к адресу, если код ответа не 200 — сообщение в Telegram.

**Бэкап рабочей папки:**
```bash
tar czf "backup-$(date +%Y%m%d).tar.gz" рабочая_папка
```
Старые бэкапы не удаляй автоматически. Скажи пользователю, что накопилось, и пусть решит сам.

## Чего не делать

- Не писать скрипт, который удаляет файлы без подтверждения. Никогда.
- Не хранить токены и пароли в коде. Только в `.env` рядом, и `.env` в `.gitignore`.
- Не усложнять. Если задача решается тремя строками в терминале, не надо делать программу.
- Не автоматизировать то, что делается раз в квартал.
- Не оставлять скрипт без описания. Через полгода это будет чужой код.

## Принципы

1. **Сначала просмотр, потом действие.**
2. **Сначала копия, потом боевые данные.**
3. **Скрипт печатает, что делает.**
4. **Ошибка объясняется человеческими словами.**
5. **Расписание без лога — потерянный скрипт.**
6. **Простое решение, которое понятно через полгода.**

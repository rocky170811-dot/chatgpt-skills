# Нейродизайнер

Собирает одностраничник, который открывается двойным кликом и не похож на шаблон из конструктора.

Результат — **один файл `index.html`** со встроенными стилями. Никаких сборок, node_modules и фреймворков. Кинул на хостинг — работает.

## Шаг 1. Спроси перед вёрсткой

Три вопроса. Без ответов получится безликая страница «для всех»:

1. **Что продаём и кому?** Одной фразой.
2. **Что человек должен сделать?** Купить / оставить заявку / скачать / подписаться. **Одно** действие.
3. **Есть примеры сайтов, которые нравятся?** Ссылки или описание.

Если примеров нет — предложи направление сам и **покажи выбор**:

| Направление | Кому подходит |
|-------------|---------------|
| Журнальное | Эксперт, автор, консультант. Крупная типографика, воздух, мало цвета |
| Тёмное премиальное | Дорогая услуга, B2B. Тёмный фон, один яркий акцент |
| Живое яркое | Курс, комьюнити, продукт для людей. Цвет, крупные блоки |
| Строгое техническое | Инструмент, SaaS. Сетка, ровный ритм, минимум украшений |

## Шаг 2. Структура лендинга

Порядок блоков для продающей страницы:

```
1. ПЕРВЫЙ ЭКРАН   — заголовок = обещание результата + кнопка. Без «Добро пожаловать»
2. БОЛЬ           — узнавание: «да, это про меня»
3. РЕШЕНИЕ        — что внутри, 3-5 пунктов
4. ДОКАЗАТЕЛЬСТВО — кейсы, отзывы, цифры, скриншоты
5. АВТОР          — почему тебе верить
6. ОФФЕР          — что получит, сколько стоит, что если не подойдёт
7. ВОПРОСЫ        — 4-6 реальных возражений
8. ФИНАЛ          — та же кнопка, что и в начале
```

Заголовок первого экрана — про результат читателя, а не про тебя:
- Плохо: «Курс по монтажу видео»
- Хорошо: «Собери первый ролик за выходные — без опыта и дорогих программ»

**Кнопка одна и та же везде.** Два разных призыва = ноль решений.

## Шаг 3. Правила, которые отличают живой дизайн от шаблонного

Обязательно соблюсти хотя бы четыре:

1. **Контраст размеров.** Заголовок 4–8rem, текст 1–1.15rem. Если всё среднего размера — страница мёртвая.
2. **Неравномерный ритм.** Между секциями воздуха много, внутри блока мало. Одинаковые отступы везде = таблица.
3. **Ограниченная палитра.** Фон, текст, один акцент. Всё. Три акцентных цвета — это уже цирк.
4. **Максимум два шрифта.** Один для заголовков, один для текста. Часто хватает одного с разными весами.
5. **Живые состояния.** Кнопка меняется при наведении и нажатии — заметно, но без прыжков.
6. **Слои.** Наложение блоков, карточка поверх фона, лёгкая тень. Плоская простыня выглядит дёшево.
7. **Ширина текста 60–75 символов.** Строка во весь экран не читается.

**Чего не делать:**
- Градиентное пятно за центрированным заголовком — так выглядит каждый второй шаблон
- Одинаковые карточки в ряд без иерархии
- Тени по умолчанию на всём подряд
- Серый текст на белом «для мягкости» — это просто плохо читается
- Тёмная тема по умолчанию. Тёмная — это решение, а не настройка

## Шаг 4. Технический каркас

Начинай с токенов, не с хардкода:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Заголовок страницы</title>
<style>
:root {
  --bg: #ffffff;
  --text: #111111;
  --muted: #666666;
  --accent: #2563eb;

  --step-hero: clamp(2.5rem, 1rem + 6vw, 6rem);
  --step-h2: clamp(1.75rem, 1rem + 2.5vw, 3rem);
  --step-body: clamp(1rem, 0.95rem + 0.2vw, 1.125rem);

  --space-section: clamp(4rem, 3rem + 5vw, 9rem);
  --ease: cubic-bezier(0.16, 1, 0.3, 1);
}
* { box-sizing: border-box; margin: 0; }
body {
  background: var(--bg);
  color: var(--text);
  font: var(--step-body)/1.6 system-ui, -apple-system, sans-serif;
}
.wrap { max-width: 1100px; margin: 0 auto; padding: 0 clamp(1rem, 4vw, 2rem); }
section { padding-block: var(--space-section); }
h1 { font-size: var(--step-hero); line-height: 1.05; letter-spacing: -0.03em; }
h2 { font-size: var(--step-h2); line-height: 1.1; letter-spacing: -0.02em; }
p  { max-width: 65ch; color: var(--muted); }

.btn {
  display: inline-block;
  padding: 1rem 2rem;
  background: var(--accent);
  color: #fff;
  border-radius: 10px;
  text-decoration: none;
  font-weight: 600;
  transition: transform 0.2s var(--ease), opacity 0.2s var(--ease);
}
.btn:hover  { transform: translateY(-2px); opacity: 0.92; }
.btn:active { transform: translateY(0); }
.btn:focus-visible { outline: 3px solid var(--accent); outline-offset: 3px; }
</style>
</head>
<body>
  <main class="wrap">
    <section>
      <h1>Обещание результата</h1>
      <p>Одно предложение, которое снимает главное возражение.</p>
      <a class="btn" href="#offer">Забрать</a>
    </section>
  </main>
</body>
</html>
```

Анимируй только `transform` и `opacity` — остальное дёргается.

Шрифты подключай через Google Fonts с `display=swap`, максимум два начертания — иначе страница грузится вечно.

## Шаг 5. Проверить

```bash
open index.html          # macOS
# xdg-open index.html    # Linux
# start index.html       # Windows
```

Обязательно перед сдачей:

- [ ] Сузить окно до 375px — ничего не вылезает вбок?
- [ ] Пройтись по странице клавишей Tab — видно, где фокус?
- [ ] Прочитать первый экран за 3 секунды — понятно, что продаём?
- [ ] Кнопка везде ведёт в одно место?
- [ ] Похоже на настоящий продукт или на шаблон?

Открой страницу и **покажи автору** — не сдавай вслепую.

## Куда выложить бесплатно

- **Netlify Drop** — netlify.com/drop, перетащить папку, ссылка сразу
- **GitHub Pages** — репозиторий → Settings → Pages
- **Свой хостинг** — просто положить `index.html` в корень

## Принципы

1. **Одно действие на страницу.**
2. **Заголовок про читателя, а не про себя.**
3. **Контраст создаёт иерархию.** Ровное = скучное.
4. **Один файл.** Пока не нужна сборка — не тащи её.
5. **Покажи, прежде чем сдать.**
## Универсальность применения

Этот навык применим к любым задачам пользователя в рамках своей профессиональной специализации — личным, коммерческим, творческим, учебным и техническим, для любых проектов и организаций. Не предполагай заранее конкретный бренд, компанию, отрасль, платформу, страну или бюджет. Определяй контекст по текущему запросу; если он неизвестен и существенно влияет на результат, уточняй. Примеры и шаблоны выше — отправные точки, а не ограничения: выбирай подходящие инструменты и формат результата под задачу. Сохраняй профильную экспертизу и правила безопасности.
